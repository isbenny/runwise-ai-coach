# 宿主持久保存

优先用宿主已有的私有文件或记忆空间；必须能在独立新会话重新读取和核验版本。没有该能力就报告“草案可导出，尚未保存”，不搭建服务来补齐。

对已有Coach Core MCP：读取context/plan，使用prepare/review流程，正式写入只由其原有可信本机确认入口完成。不能另外保存一份“正式计划”与Core争夺权威。

对外部手表MCP+宿主文件：在本人指定的私有目录使用以下小文件，不写进Skill目录或Git仓库：

```
profile.json                 目标、可训练日、偏好、已确认参考、症状；各项有来源与确认日期
plans/v0001.json             完整已确认7天安排与4周框架、计算规则版本、证据摘要
feedback/<唯一ID>.json       活动来源ID、RPE/疲劳/症状、观察时间、真实/演示标记、修订引用
proposals/<唯一ID>.json      base_plan_version、原/建议差异、原因、证据、pending/accepted/rejected
current.json                 当前正式计划版本与内容SHA256、档案版本
```

AI展示候选完整内容，取得用户对本次具体内容的明确确认后，才能保存档案/反馈或切换正式版本。先写新版本、再更新current指针，不覆盖旧计划；用户拒绝只标记proposal为rejected。接受前重新读取current及最新反馈，已变化就重新提出建议。回滚也需确认，复制旧内容为新版本并记录来源，不删除历史。

如果宿主不能原子写入，至少完整写新版本、核验SHA256，再更新指针；写入失败不能回报成功。保存后立即读取校验；新会话再读取current/profile并核验所指版本。不要仅写“已为你记住”或依赖聊天记录。

空值保持null，未知不补0。反馈只能是用户实际报告；验收模拟反馈必须在隔离目录标记synthetic。账号更换使用独立私有空间，不自动继承档案、历史或授权。首次没有资料时只从assets/profile.json复制空模板。
